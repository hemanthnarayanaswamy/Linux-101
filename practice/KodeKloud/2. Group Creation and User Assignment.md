
# 2. Group Creation and User Assignment

We can execute the commands with `ssh`, but `ssh` itself does not have an option to pass the login password directly.

```bash
#-t means: allocate a remote TTY.

# -tt in ssh forces allocation of a pseudo-terminal on the remote server.
#-tt means: force it more strongly, even when ssh thinks it is running non-interactively, such as inside a script.

ssh -tt user@server "sudo useradd rajesh"
# Run command directly into remote server
```
For scripting, we can use `sshpass`, The `sshpass` command is a utility designed to facilitate non-interactive SSH password authentication. It is particularly useful for automating SSH logins in scripts, where manual password entry is not feasible.

```bash
sshpass -p 'your_password' ssh -tt tony@stapp01 "sudo groupadd -f nautilus_admin_users"
```
- For one by one users you can manually do this. 

```bash
sshpass -p 'your_password' ssh -tt tony@stapp01 "
  sudo groupadd -f nautilus_admin_users
  id rajesh >/dev/null 2>&1 || sudo useradd rajesh
  sudo usermod -aG nautilus_admin_users rajesh
"
```
- or you can execute a bash script like this. 

```bash
#!/usr/bin/env bash

GROUPNAME="nautilus_admin_users"
USERNAME="rajesh"

declare -A servers
servers['stapp01']='tony'
servers['stapp02']='steve'
servers['stapp03']='banner'

declare -A userpass
userpass['tony']="Ir0nM@n"
userpass['steve']="Am3ric@"
userpass['banner']="BigGr33n"

for app in "${!servers[@]}"; do
    user="${servers[$app]}"
    password="${userpass[$user]}"

    sshpass -p "$password" ssh -tt "$user@$app" "
        sudo groupadd -f $GROUPNAME

        if ! id $USERNAME >/dev/null 2>&1; then
            sudo useradd $USERNAME
        fi

        sudo usermod -aG $GROUPNAME $USERNAME
    "
done
```
> sudo asks for a password prompts, `sshpass` only handles the SSH login password, not the sudo prompt. 
> In that case you’d need passwordless sudo or use `sudo -S`.

`sshpass` can answer the password prompt, but it ***does not handle the first-time host authenticity prompt well.***

```bash
The authenticity of host 'stapp01' can't be established.
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```
When you typed yes, SSH saved that server’s host key into:
`~/.ssh/known_hosts`
- After that, `sshpass` worked because SSH no longer needed the interactive yes/no confirmation. 

To Fix it, **pre-load the host keys before running the script:** It is recommended.

```bash
mkdir -p ~/.ssh
chmod 700 ~/.ssh

ssh-keyscan -H stapp01 stapp02 stapp03 >> ~/.ssh/known_hosts
chmod 600 ~/.ssh/known_hosts
```
**Not Recommended**, But we can skip the host key verification

```bash
sshpass -p "$password" ssh -o StrictHostKeyChecking=no -tt "$user@$app" "hostname"
# This should work even when you have never ssh into àhost
```
