# Linux User Setup

There are scenarios where you might want to create users who are not allowed to log in interactively. These non-login users serve various purposes, such as running system services, managing daemons, or for security reasons.

### Why do we even need users on a Linux system?
A Linux system can host multiple users and processes simultaneously. Each user account acts as an isolation layer, defining who can log in, what files they can access, and what actions they’re allowed to perform. This control mechanism helps enforce key security principles:
- **Authentication**: verifying who is trying to access the system.
- **Authorisation**: determining what the user is allowed to do.
- **Principle of Least Privilege (PoLP)**: ensuring that every user or process has only the minimal permissions required to perform its function and nothing more.

### Service Account in Linux
A service account is a user account that is created specifically for an application or a service. Service accounts are used to provide a security context in which the application or service can run.
* Don't give login access to **service Account** and also for permission don't give `root` access, provide more role based or access control. 

### [What is a Non_interactive Shell ?](https://linuxvox.com/blog/linux-user-no-login/)
The shell associated with a user account determines whether the user can log in interactively.

A ***non-interactive shell*** (like `/usr/sbin/nologin` or `/bin/false`) prevents the user from accessing the system directly. 
    - Instead of opening a command prompt, it immediately exits or displays a message. 
    - This is ideal for system users who only need background-level access for services, hence reducing attack surfaces and improving system security.

While both `/usr/sbin/nologin` and `/bin/false` can prevent interactive logins, `/usr/sbin/nologin` is preferred because it’s specifically designed for this purpose. It provides a clear message, like *‘This account is currently not available’*, making it easier to troubleshoot. In contrast, the `/bin/false` method is a legacy approach that simply exits without feedback, which can be less intuitive.

### How Non-Login Users Differ from Regular Users#
Regular users are typically created for human users to log in, perform tasks, and access resources. They have a home directory, a shell for interactive use, and can execute commands. Non-login users, on the other hand, usually have no home directory or a restricted shell, and their primary purpose is to run specific services or scripts.

### [Useradd vs Adduser: What's the Difference?](https://linuxhandbook.com/useradd-vs-adduser/)

`Useradd` is built-in Linux command that can be found on any Linux system. However, creating new users with this low-level is a tedious task because it doesn't create the home directory and user password by default.

`adduser` is a high-level, interactive Perl script (not available on all distros) that acts as a wrapper around useradd. It guides you through prompts to set a password, create a home directory, assign a default shell (usually Bash)

## Task 1: Linux User Setup with Non-Interactive Shell

For the task we need to create a user with *non-interactive shell*. 

`--system`/`-r`: Creates a system account. typically for services, with a UID below 1000. **No home directory** is created unless `-m` is specified.
                    * It creates a temp file in `/etc/passwd` but that directory won't exit in real.
`--shell`/`s`: assign the shell which we are going to use.
`-M`/`--no-create-home`: do not create the user's home directory

```bash
export pass="password"

sshpass -p $pass ssh -tt banner@stapp03 "
> sudo useradd --system --shell /usr/sbin/nologin james
> id james
> cat /etc/passwd | grep james
> "
```

## Task 2: Service User Creation without Home Directory

### System Users
System users are a like normal users but for are set an organizational purpose. The only difference is :
    * They don't have an expiry date ( no aging set )
    * Their uids are below `999` like set on `/etc/login.defs`

Create a system user without a home directory:
```bash
useradd -r -M serviceuser
```
`--system`/`-r`: Creates a system account. typically for services, with a UID below 1000. **No home directory** is created unless `-m` is specified.
                    * It creates a temp file in `/etc/passwd` but that directory won't exit in real.

```bash
sshpass -p $pass ssh -tt steve@stapp02 "
> sudo useradd --system -M mark
> id mark
> cat /etc/passwd | grep mark
> "
```
